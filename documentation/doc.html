Nexora ERP: Product & Technical Documentation

Nexora is an ERP for service companies (agencies, consultancies, studios, IT services). It follows the whole chain of the business: people → clients → projects → hours → invoices → cash → profit. This document describes what has been delivered, how each module behaves, the business rules behind it, how the code is organised, and what remains to be built. It follows the Nexora ERP cahier des charges.

Next.js 16 · React 19 · TypeScript Tailwind CSS v4 · Nexora DS 9 languages incl. Arabic (RTL) 398 unit tests · Playwright e2e Demo data in the browser (backend = Phase 7)

01What Nexora ERP is

Service companies sell time and expertise. Their questions are always the same: who works on what, how many hours, what can we bill, who has not paid, and are we making money? Nexora answers them in one tool instead of spreadsheets plus separate HR, time and invoicing apps.

Run the team

Employees, departments, rates that change over time, working days, holidays, leave and capacity.

Deliver the work

Clients, projects, tasks, milestones, budgets, health, and the hours people log on them.

Get paid and measure

Invoices of every type, payments, credit notes, receivables, expenses, margin and analytics.

Important: the current version is the complete front end running on demo data stored in the browser. Every screen, rule and calculation works, but data is not shared between users until the real backend (Phase 7) is connected.

03Run it locally

git checkout main && git pull
npm install

# .env.local
NEXT_PUBLIC_API_URL=http://localhost:4000/api
NEXT_PUBLIC_DEMO_MODE=true

npm run dev

Open http://localhost:3000 and click Instant Demo Preview on the login page. Use the workspace switcher in the top bar to move between the two demo companies (Atlas Consulting, Northwind Studio).

  • Pages look old after a pull → stop the server, rm -rf .next, start again, hard-refresh the browser.
  • Reset the demo → DevTools → Application → Local Storage → delete the nexora: keys.
  • npm run build refuses NEXT_PUBLIC_DEMO_MODE=true on purpose, so a demo never reaches production by accident.
  • Checks: npx tsc --noEmit, npm run lint, npx vitest run, node scripts/check-i18n-sync.mjs, npm run e2e.

05Roles & permissions

Each workspace member has a role; screens show or hide actions with permissions. In this front-end version permissions only control the interface; Phase 7 enforces them on the server.

RoleTypical rights
AdminEverything, including settings, period lock, costs and data export
ManagerProjects, team, approvals of their people, costs if granted
AccountantInvoices, payments, credit notes, receivables, expenses, costs
EmployeeOwn timesheet, timer, leave and expenses; assigned tasks
ClientReserved for the client portal (Phase 5)

Key permissions: employees:*, clients:*, projects:*, time:track, time:approve, invoices:*, costs:read (hourly costs and margins are hidden without it), analytics:view.

07Workspace settings

  • Company: legal name, trade name, ICE (15 digits, required on Moroccan invoices), tax ID, trade register, address, base currency, fiscal-year start, week start, time zone, invoice number format (e.g. INV-{YYYY}-{SEQ}).
  • Period lock: a date on or before which nothing can be changed (hours, invoices, expenses), for closed accounting periods.
  • Data: export all workspace data as JSON; delete the workspace's demo data.
  • Lists: departments, public holidays, leave types, expense categories, task labels.
  • Approvals: who approves timesheets, leave and expenses (manager, project manager or a named person; one or two steps).

08Employees (HR)

  • Profile: job title, department, manager, role, employment type, hire date, skills.
  • Statuses: starting, active, on leave, notice, inactive.
  • Working days and weekly capacity (e.g. a part-timer working Mon–Wed, 20 h) – used for capacity and utilization.
  • Rate history: hourly cost and billable rate with an effective date and a reason. Past work keeps the rate valid on its date.
  • Costs and margins are only visible with the costs:read permission.

09Clients (CRM)

  • Legal name, ICE, tax ID, billing address, currency, invoice language, payment terms, account manager, contacts, status (lead, active, archived).
  • Rate card: special rates for a person or a job title for this client.
  • A client with invoices cannot be deleted (archive it instead). Changes are written to the audit log.

10Projects & tasks

  • Budget types: hourly (time & materials), fixed price, retainer (monthly amount with included hours and an overage rate), non-billable (internal).
  • Views: board (Kanban), list, milestones, team. Filters by assignee, label and priority; filters can be saved as named views.
  • Tasks: status, priority, assignee, milestone, due date, estimate, labels, subtasks, comments with @mentions and an activity history of every change.
  • Health is calculated from schedule and budget; a manager can override it with a reason.
  • Budget alerts at 80% and 100% of the budget; fixed-price projects show the share already billed.

11Time tracking & approvals

  • Weekly timesheet per person and project/task; timer in the top area and a quick log; copy last week.
  • Hours are rounded to 15 minutes; max 24 h per day; only team members of the project can log; closed projects refuse hours; the gap to expected hours (capacity less leave and holidays) is shown.
  • Statuses: draft → submitted → approved, or sent back with a reason. Approved hours can be reopened by a manager if not yet invoiced.
  • On approval, the bill rate and cost rate are frozen on each entry.
  • Approvals page: one card per person and week with hours per project and billable value; approve all at once.

12Invoicing & payments

Invoice typeHow it is built
HoursFrom approved, unbilled hours; lines grouped by person, task or day
Fixed shareA percentage of a fixed price; never more than the price
MilestoneThe amount due when a milestone is reached
RetainerMonthly amount, plus hours beyond the included ones at the overage rate
DepositAn advance; deducted automatically on the next final invoice
FreeAny manual lines
Credit noteCancels all or part of an issued invoice (own CN- numbering); can free the hours for rebilling
  • Several tax rates per invoice (one per line), withholding tax, invoice currency with exchange rate to the base currency.
  • Partial payments (date, amount, method, reference); balance due after payments and credit notes; marked paid automatically when fully paid.
  • PDF with company identity (ICE, tax ID, trade register), tax breakdown and balance; delivery log when sent.
  • CSV exports of invoices and of payments for the accountant.

13Receivables

Open balances per client, split by lateness: not yet due, 1–30, 31–60, 61–90, over 90 days, in the base currency, with totals and CSV export. Clients with money over 30 days late are flagged as high risk on the Analytics page.

14Expenses & profitability

  • Expenses with category, project, receipt, billable flag; submitted → approved / rejected → reimbursed; billable expenses can be re-billed on the next invoice.
  • Profitability per project: revenue, cost of hours, expenses, margin and budget usage.

15Planning & leave

  • Timeline and calendar of projects, milestones and leave.
  • Workload: planned and logged hours against each person's capacity.
  • Leave requests with types from settings and approval; approved leave reduces capacity.

17Business rules

RuleBehaviour
Bill ratePerson on the client's rate card → job title on the rate card → client rate → employee's rate on the date of the work
Rate freezeApproval stores the bill and cost rate on each entry; later rate changes never change approved work
Invoice numbersGiven at issue, gapless per fiscal year; drafts have no number; issued invoices are never deleted, only credited
Period lockNo create, edit or delete on or before the lock date
Self-approvalNobody approves their own hours, leave or expenses
RoundingHours to 15 minutes; amounts to the cent per line; tax computed per rate
VoidingAn invoice with payments cannot be voided; use a credit note
Revenue (analytics)Approved billable hours on hourly projects × frozen rate + fixed, milestone and retainer invoices − credit notes
Gross marginRevenue − cost of all logged hours − approved expenses
UtilizationBillable hours ÷ available hours (working days × hours per day, less leave and holidays); target 75%

20Demo data

Two workspaces are seeded, relative to today so the demo never looks old:

  • Atlas Consulting (EUR): 10 employees in 5 departments, clients Orbit Logistics, Helio Energy, Medica Health, Vela Retail (lead), Kappa Bank (archived); current projects and a year of finished ones; about 1,500 hours; monthly invoices with payments; some invoices open, partly paid and overdue (so receivables and risk alerts have content); a fixed-price share invoice.

  • Business logic is pure and tested (billing.ts, invoice-builders.ts, rates.ts, approvals.ts, planning.ts, kpis.ts, profitability.ts, analytics.ts), so the backend can reuse the same rules.
  • API functions are the seam: today they read and write the demo store; in Phase 7 each body becomes an HTTP call and the screens stay the same.
  • Stack: Next.js 16 (App Router), React 19, TypeScript strict, Tailwind v4, TanStack Query, Zustand, next-intl, Recharts, jsPDF.

22Design system

  • Nexora DS tokens (DS-00 to DS-02): operator gray and tech blue ramps mapped to semantic tokens; low-chroma status colors always paired with a label or icon; dark mode from the same ramps.
  • Radius 2/4/8/12/16/24 px, three elevation levels; Inter for the interface, Roboto Mono for codes and numbers, a serif for side-panel titles.
  • Layout: top tab bar with sections, icon rail with pages, page header panel, metric cards, tables, floating rounded side panels.

23Languages

English, French, German, Spanish, Arabic (right to left), Urdu, Hindi, Russian and Chinese. Texts live in src/messages/*.json; scripts/check-i18n-sync.mjs fails CI if a key is missing in any language.

24Quality & security

  • CI on every pull request: typecheck, lint, i18n sync, 398 unit tests, production build, Playwright end-to-end tests, dependency audit, and a check that demo mode is blocked in production builds.
  • CSV exports neutralise spreadsheet formulas; PDFs and HTML reports escape all text; API requests time out.
  • Known limit of this version: permissions are enforced in the interface only and data lives in the browser – both are solved by the backend (Phase 7).
