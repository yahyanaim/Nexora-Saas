# Nexora SaaS — Code Review & Deep Audit (2026-10)

_Supersedes `docs/CODE_REVIEW_AND_AUDIT.md`._
## Verification status
- `node_modules` is not installed in this container, so lint/vitest could not run. `tsc --noEmit` (global TS) fails on `tsconfig.json:26`: `baseUrl` is deprecated (TS5101) — a real issue once TS 6/7 lands.
- `npm audit --omit=dev`: 4 vulns (1 high: `brace-expansion`, 2 moderate: `fast-uri`, `ip-address`, 1 low) — all fixable via `npm audit fix`.

## Findings (ranked)

### High
1. **Passcode lock screen is dead code.** `src/components/shared/dashboard-layout.tsx:15-18` reads `isPasscodeLocked` from `useAuthGuard()`, but `AuthGuardProvider` (`src/contexts/auth-provider.tsx` ~L230 `value`) never sets it. `<LockScreen>` never renders; the header lock icon and passcode-dialog labels are also always "off". Fix: `isPasscodeLocked: user?.isPasscodeLocked`.
2. **Demo-mode checks bypass the production guard.** `isDemoMode()` (`src/lib/auth/demo-mode.ts`) refuses demo mode when `VERCEL_ENV=production`, but `team-apis.ts` and `files-api.ts` check `process.env.NEXT_PUBLIC_DEMO_MODE` directly, and 17 of the api modules don't use `isDemoMode` at all. The build guard (`next.config.mjs`, `scripts/prebuild.js`) only covers Vercel — on Fly (a `@flydotio/dockerfile` devDep is present) / Docker nothing stops `DEMO_MODE=true`. With demo mode on, `loginApi` signs in **any** credentials as an admin when the backend errors (`auth-apis.ts` ~L66: `DEMO_USERS[email] || DEMO_ADMIN_USER`). Fix: use `isDemoMode()` everywhere and fail the build when `NODE_ENV=production && DEMO_MODE=true` unless an explicit `ALLOW_DEMO_BUILD` is set.
3. **`isBackendUnreachable` is too broad** (`src/lib/myapi/client.ts`): it treats **404** and any non-Axios error as "unreachable", so with demo mode on, real 404s/bugs quietly turn into fake localStorage data.

### Medium
4. **Edge guard checks only that the cookie exists** (`src/proxy.ts`). This is documented, but any `token=x` cookie gets the dashboard shell rendered. That's OK only if every page fetches data client-side with backend auth — worth confirming. Also: the locale regex `^/([a-z]{2})` accepts any two letters (`/zz/dashboard` → redirect to `/zz/auth`); validate against `routing.locales`. The redirect also drops the return URL (`?next=`).
5. **CSP is weak** (`next.config.mjs`): `'unsafe-eval'` + `'unsafe-inline'` in script-src, and `connect-src https: wss:` lets the page connect to any host. The localhost connect entries ship to prod. Use nonce-based CSP in proxy and limit connect-src to the API/socket origins.
6. **Refresh interceptor** (`client.ts`): `isAuthRoute` uses `url.includes` (matches `/auth/me` inside other paths). Also, any concurrent 401 that arrives after the refresh finishes starts a second refresh, because the `finally` clears `refreshPromise` before queued callers re-check. Minor race; fine for most backends.
7. **`innerHTML` with translated strings** (`files-chunks/file-dialog.tsx:187`): low XSS risk (the strings come from i18n), but it's imperative DOM changes inside React. Replace with state-driven JSX.
8. **The client-side passcode flag is in localStorage** (`passcode-dialog.tsx:85`) and **demo team data is persisted in localStorage** (`team-apis.ts`). `JSON.parse` output is used without validation.
9. **Upgrade-required handler** fires `toast` + `router.push` once per failing request — parallel queries cause a toast storm. Debounce it.

### Low / code quality
10. `auth-provider.tsx`: the `useMemo` for `user` depends on `baseUser`, which is a new object every render, so the memo never caches and the `value` context object (not memoized) re-renders every consumer. `refetchUser` is an inline lambda.
11. The guard redirects in `auth-provider` use `pathname.includes("/auth")`, which also matches `/dashboard/authors`. Use `startsWith`.
12. Noisy `console.error` in every api module (≈50 sites) logs full error objects in prod. Centralize in the interceptor.
13. `src/store/auth/auth-store.ts` (redirect state) looks unused. `src/hooks/.gitkeep` is clutter. `scratch/*.json` lint dumps are committed. The package name `volix-saas-starter` and the "Volix" comments don't match the "Nexora" brand.
14. Dependency bloat: two UI systems (`@carbon/react` + Radix/shadcn), `react-window` + `@tanstack/react-virtual`, `motion`, `jspdf`, `three` types, and `sass` alongside Tailwind 4. `shadcn` (a CLI) and `@types/canvas-confetti` belong in devDeps. `eslint-config-next` pinned to 16.1.6 while next is ^16.3.6.
15. The catch-all `app/api/[...catchall]/route.ts` returns 410 — fine, but it means no BFF; all auth cookies must be cross-site-capable from the API domain (SameSite=None + CORS credentials). Document this or proxy via rewrites.
16. Tests: about 12 test files, covering only lib/auth basics. No tests for the proxy redirect locale logic, interceptor races, or any page.

### Positives
Zod env validation, centralized `can()` RBAC clearly labeled UI-only, HttpOnly cookie design, strong security headers (HSTS, frame-ancestors, COOP), `dangerouslyAllowSVG:false`, sanitized chart CSS, i18n sync script.
